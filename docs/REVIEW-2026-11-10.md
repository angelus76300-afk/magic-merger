# Review of the whole project, 10 November 2026

Asked for by the owner: step back from the queue, judge the project as a whole across seven areas, report the five biggest improvements, and build the first. `main` was at `3cac133`. This file is the full review; the short version went to the planner for the owner's brief.

How it was done. Five independent reviews ran side by side, each read only, each returning evidence (file and line, run ids, query results): the code, GitHub and Cloudflare, the development process, the live library (40 programs read, all 483 run in Node), and a 50 minute play session on the owner's phone sizes. A game designer then judged the loop and the plan from that evidence. The reviewing session read the docs, the history, the prompts and the test run itself, chose what matters, and built the first improvement. Every number below was measured today unless it says otherwise. What could not be checked is listed at the end.

One deviation from the brief, said plainly: the play session ran on staging (the same commit as production, a copy of the live library, real Claude calls), not on production. The playtester's own rule forbids production, and playing there with the admin token risks writing the owner's account. Production was loaded only as a stranger, at both sizes: the gate is clean.

## 1. How we got here

Read from `docs/ROADMAP.md` ("Done in" 2.0 to 4.5.2), the git history, the last 42 pull requests and the ledger.

1. **Spells are programs** (the first rewrite). It is the game. Everything good on the island since comes from it.
2. **The test run against a control island** (3.3) and **every version kept** (the `programs` table). These two made every later fix possible without losing anything. No live program crashes today: 0 of 483.

## 3. GitHub and Cloudflare

**1. The repository is public, and the pipeline is still built to save 2,000 minutes.** The API returns `private: false` and a run's billable time is 0. `docs/DAILY.md`, `ci.yml`, `loop-metrics.mjs` and the brief still count against 2,000. As a private repository, 7 and 8 November alone would have billed about 2,223 minutes. On a public one this costs nothing. So `npm test` can go back to CI, the reviewer's `tests=pass` (a line a builder could write, since both post as the owner) can go, and the Night and the Judge can be scheduled workflows again.

**2. Any pushed branch can read every repository secret.** `preview.yml` and `ideas.yml` run on `pull_request`, from the branch's own copy of the workflow, with `CLOUDFLARE_API_TOKEN` and `MM_TOKEN`. A branch that edits them prints the token on its first push, before CI, review, class or Gate. The class only stops the merge. Every session can push a branch, and every session's environment also holds the production `ADMIN_TOKEN` and the account wide `CLOUDFLARE_API_TOKEN`. `main` shows `protected: false`.

The smallest fix: the owner deletes the two production credentials from the cloud environment and moves the repository's production secrets into a GitHub environment restricted to `main` (20 minutes; free on a public repository). A session puts the Night and the Judge back on a schedule and adds a workflow that runs the one spell rewrite by name.

**3. A docs merge right after a code merge leaves the code undeployed.** Deploy run 42377806328 (7 November 13:37): `deploy: skipped`. The code merge's run stopped because `main` had moved; the docs merge that moved it starts no deploy. Production stayed behind `main` for 21 minutes, until an unrelated merge. Nothing would have said so before the night.

**4. The budget check reads the whole month of `spend` on every paid call.** 7.90 of 16.70 million rows read in ten days (47%). It costs 4,205 rows per call today and grows by about 470 a day. A busy day late in a month would read 16 to 30 million rows against the free plan's 5 million a day; D1 then refuses queries and every paid call fails. Pull request #101 covers the cron's scans; the hold needs running totals.

**5. The Gate.** It trusts markers written by the owner's account, which is every session. For 24 of 42 merges the "owner's yes" was a label the planner wrote. Free on a public repository and simpler: a ruleset on `main` with required checks and no bypass, auto merge, and an environment with the owner as required reviewer for red deploys (one tap in the GitHub app). `risk.mjs` and the deploy check stay; they carry the judgment.

**6. The rollback has never run.** 40 deploys, 0 rollbacks, 0 issues labelled `rollback`. The live smoke test never signs in, so it sees the invite gate and no merge, spell or island. A migration is applied before the deploy and stays if the Worker rolls back. One drill on staging would settle whether recovery works.

**7. Money.** $18.95 of $48 this month; 56% is two one-offs (the version bump and the refresh). Run rate since 4.2: about $32 a month. Opus is 89%. Invited players are 15% of spend; the owner's account and the game's own jobs 47%. A new item costs $0.014 expected and $0.029 measured. Background jobs cost $4.40 to $6 a month with nobody playing.

**8. Smaller things.** Staging follows `main` once a day, since Gate merges start no push workflow (1 of 42 did), and its deploys carry no commit message. The smoke step prints the month's spend into a public log. Playwright and an `npx wrangler` tree run unpinned next to production tokens. Scheduled runs arrive 6 to 10 hours late. `spend` stores no token counts, so the prompt cache's hit rate cannot be read.

**Stop.**

3. **Accepting the smoke test as "claim reproduced".** Reviewers skip the cast because a cast on staging costs money. Give them a free path: a fixture or a lab scenario per claim, run in Node.
4. **Adding rules.** Delete what a script enforces (about 900 words), what is obsolete (Actions minutes), and what is said three times. One page a builder reads, one a reviewer reads.
5. **One unrestartable planner as the only memory.** Its context has been compacted once already; the list's working copy and the owner's words live in its scratch files. Approvals and the queue belong in the repository or the issue, so any session can pick them up.
6. **Classing so much red.** When 43% of work is red and the planner writes the yes, red has stopped meaning "the owner must look". Keep red for money, players' data, spells in bulk, public and credentials. Make prompt text and pipeline docs amber with a measurement attached.

**Start.**

1. **A weekly subtraction.** One session a week whose only output is things removed: a job, a rule, a script, a cap.
2. **A sweep for stuck work.** #71 (a player's rain fix) had its OK on 8 November and was never reviewed. #93 is 10 lines with three passes, still open.
3. **Honest metrics.** "Found by: owner" mixes requests with bugs, and "no owner action" now counts labels the planner writes itself.
4. **Reviews that play the claim**, with the playtester agent on the preview, for anything visible.

### The causes

The quality of an item is decided in four places, and each had a fault a single feature session would not see.

1. **The promise.** The intent call names up to two intents from ten. Only `protect` is tested, so only `protect` matters, and it is handed out freely: as a second intent it is wrong 62 times in 64 (Gold, Clay, Ice, Werewolf, Dinosaur). The writer is then told its test will attack a village and to raise a ward. The probe measures whether the village survived. So the cheapest way to pass is a dome, and the gate rewards it. The test became the target.
2. **The prompt.** One text of about 4,000 words, grown a paragraph per version. Its examples teach what its rules forbid: four of eight open with a chime, the Fireball example is the "orb and explosion" its own rule 1 warns against, and the artifact section still said "build its look with structures or voxels" three paragraphs after forbidding it. It never said what the engine drops. It asks for code at once, with no moment to say what the name promises.
3. **The engine.** It takes what it understands and ignores the rest without a word. The writer never learns; the test cannot tell.
4. **The gates.** For a spell the test asked one thing: did anything visible change (3 cells, 4 blocks, 1 creature, or a body in flight for half a second). Nothing asked whether it was what the name says.

A fifth, found on the way and not a writer's fault: **a monster placed by a village is dead in seconds.** The practice island and a player's island agree: villagers fight what scares or hunts them, and a creature of the night arrives asleep. One villager on guard kills a Werewolf of 80 health in 4 seconds; three Undead of 140 each are dead in 10. This is an engine rule to change (section 7), and it explains much of pattern 4.

### Measured: before and after on the same 20 names

The set: 20 live items chosen by the library review before any change was written, all seven kinds and all six tiers, 8 that break their promise today, 6 that half keep it, 6 that keep it as controls (Life, Shadow Step, Arcane Shield, Divine Radiance, Extinction Event, Werewolf, Undead Horde, Astronaut, Guardian Angel, Rocket Fleet, Aegis, Leprechaun Gold, Crypt, Lich Tower, Sunken City, Village, Cave, Universe, Meteorite, Wasteland). None of these names is used as an example in the new prompt (the first draft did use some; they were replaced before the measurement).

The method, and its limit. Each name was written once per arm from the exact system prompt and message the Worker builds (`spellSystem` with the live helpers, `spellUserMessage` with the stored entry, recipe, tier, kind and intents), by a Claude Code subagent on the model production uses (Haiku up to grand, Opus above), one fresh agent per program, told to read nothing else. The new arm's intents came from the new intent prompt the same way. Helpers were inlined as the Worker does. Each program then went through the test run in Node. This is not the production path: no JSON schema is enforced, the agent harness differs from the API, and each name was written once. It compares two prompts under the same conditions; it does not predict production rates. The real path can be measured on a preview once staging has budget (it has $0.13 left).

## 7. The game itself

Played on staging, at `main`'s commit, for about 50 minutes at 344 by 882 and 700 by 830, with touch: 47 merges, 24 casts, a ten minute watch, every tab, a reload. Headless Chromium with software WebGL: frame times and sound are not a phone's.

**The first ten minutes.** Items shown in 1.0 s, the first merge answered at 13.7 s, the card at 15.7 s, the island at 25.3 s. The first cast tap, at 36.6 s, was swallowed: a ten line toast ("New on islands this week") covers the top third at 344 wide, a tour of the wonders moves the camera, and a tap during the tour casts where the tour's camera points. The newcomer never sees their first spell. Nothing says that one finger turns and two pan, that the list scrolls, or how to put a spell away. At 344 the list shows 6 of the 8 forces, and 3 rows once there are 59 items: a new item lands out of sight.

**The core loop.** Minutes 0 to 4 are the best of the game: 28 pairs of forces, every one new and sensible, a second each. Then the climb is over: a grand spell comes from the first merge and a cosmic place from the seventh. On the island, the big spells are a show (Tidal Wave, Meteor Strike, Supernova, Firestorm) and the small things are a few blocks, often under a dome (Steam a pale cube bigger than a house, Stone Wall a grey stub in a white dome, Hot Spring four teal blocks).

**It is two games.** Merging never asks about the island, and the island never asks for a merge. The first challenge is won with zero merges. 338 of 483 live programs were never cast by anyone.

**The simulation, as a player sees it.** In ten minutes untouched, under 1% of pixels changed per 30 seconds by day. Day, night with torches, rain; a road went from 18% to 27% laid. No birth, hunt or new building was seen. The stories exist: a merchant found an old coin, a guard chased a rabbit. They exist as text on a card that a tap must find. What the engine models is far ahead of what the screen shows.

**What to do, in order** (the designer's scores, impact times confidence times ease):

1. **A first cast seen** (648). No toast and no tour before the first cast has landed; a tap during a tour ends it and does not cast; the camera holds the cast for three seconds; the new item is scrolled into view at 344. One number to hold it to: seconds from load to a first cast seen, on three fresh profiles at 344 by 882. Today: never. Target: under 60.
2. **Creatures that live** (448). A placed creature arrives awake. A lone villager flees what has twice its health; guards attack in threes. A kind may not grow past three times what was cast. Target: the median daytime life of a placed monster from under 10 seconds to over 120.
3. **Items that keep their promise** (240): this pull request.
4. **One game.** The smallest join that hands players no idea: once a session, one trouble the engine already has (a wildfire, a drought, high water, a night raid) starts on the player's own island, shown only as what is seen and a line of the chronicle. It needs tiers that climb, or Supernova answers everything. A question for the owner.
5. **Morning on the island.** The first open of a day lands where the camera was left, with a card of three lines: what happened last session (from the story log, no call), how many daily items are unfound and who found the last, today's trouble.

**Stop building**: depth nobody can see (crafts, vehicles, one idea a day) until a ten minute watch shows a birth, a hunt and a building going up from the default zoom; content written ahead of its players; process as a product.

## What could not be verified

1. Rulesets on `main`, repository settings, the Cloudflare plan and the token's scopes: not readable with the tools at hand. Only the classic `protected` flag (false) was read.
2. The production path of the writer after the change (JSON schema, batch, cache): measured through subagents, once per name. A preview run needs staging budget.

6. The prompt cache's hit rate: token counts are logged, not stored.

8. The reviews were run by agents of this session. Their numbers were spot checked where this session depended on them (the intents, the wards, the dropped effects, the deaths by villagers were all reproduced here); the process and operations counts were not recounted.
